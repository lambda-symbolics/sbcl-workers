#+TITLE: sbcl-workers
#+STARTUP: content

=sbcl-workers= manages named, persistent SBCL subprocesses through a readable
S-expression protocol. Each worker keeps its own heap, can move between working
directories, and can be reset independently.

Process separation is a reliability boundary. Evaluated forms have the user's
privileges.

* Environment and pool

The host supplies the command that starts a pristine protocol runtime. This
keeps the library independent of any executable, build system, or application:

#+BEGIN_SRC lisp
(defparameter *environment*
  (sbcl-workers:sbcl-worker-environment-create
   :pristine-command '("my-lisp-application" "--worker")
   :working-directory #P"/srv/project/"
   :image-root #P"/srv/state/lisp-images/"))

(defparameter *pool*
  (sbcl-workers:sbcl-worker-pool-create *environment*))

(defparameter *repl*
  (sbcl-workers:sbcl-worker-pool-start *pool* "compiler" "pristine"))

(sbcl-workers:sbcl-worker-request
 *repl* :eval '(:forms ("(+ 20 22)")))
#+END_SRC

An =:eval= or =:compile= request carries =:forms=, a non-empty list of strings
that each hold exactly one form. The worker reads and evaluates them in order,
reading a form only after the previous one ran, so a later form may use a
package an earlier one loaded. The response carries the last form's values and
the output of all of them; a failure stops the sequence, keeps the effects of
the forms before it, and reports =:form-index= and =:form-count=.

The pristine command must load =sbcl-workers= and call
=sbcl-workers:sbcl-worker-main=. It may also be a function of no arguments
returning such a list; it is called at every pristine start, so a host can boot
a prebuilt core while it is current and fall back to loading source otherwise.
Applications can configure:

- the evaluation package
- handshake tag
- protocol version
- matching SBCL source environment variable

=sbcl-worker-name-p= checks the accepted one-to-eighty character worker-name
syntax.

Requests run with the standard printer settings; only the protocol line itself
is printed readably, so user code may print conditions and other unreadable
objects. Every response carries the request's captured =:output=. An =:error=
response adds the condition's =:message= and a =:backtrace= taken where the
error was signaled, so a failed system load still shows the compiler's
diagnostics and the failing frames.

* Worker images

=sbcl-worker-save-image= forks a short-lived saver from a running worker. The
parent continues running while the library probes the unpublished core and then
atomically publishes its immutable directory and readable manifest. Manifests
record:

- the exact SBCL, operating system, and architecture
- parent image
- creation time
- durable note
- optional host source revision

Saved cores are accepted only by an exactly compatible runtime. =pristine= is a
reserved virtual base.

* Operations

The built-in runtime handles:

- evaluation and compilation
- ASDF or Quicklisp system loading
- description
- source lookup for loaded definitions, mapping SBCL's own into matching SBCL source
- ASDF tests
- image saving

Responses contain only readable Common Lisp data.

* Optional host callbacks

Load =sbcl-workers/host-callbacks= on the host, then execute an ordinary operation
with =sbcl-worker-host-request=. The library loads the optional runtime into the
persistent worker through ordinary evaluation; pristine workers and saved images
use the same stdin/stdout transport and process manager.

#+BEGIN_SRC lisp
(asdf:load-system :sbcl-workers/host-callbacks)
(sbcl-workers:sbcl-worker-host-request
 *repl* :eval
 '(:forms ("(sbcl-workers:sbcl-worker-host-call '(:lookup \"name\"))"))
 :dispatcher (lambda (payload &key context identity cancelled-p)
               (declare (ignore context identity))
               (if (funcall cancelled-p)
                   (error "Cancelled")
                   (list :found payload)))
 :context opaque-host-accounting-context
 :worker-context '(:budget 100)
 :cancel-p (lambda () request-cancelled-p)
 :request-limit 1048576
 :result-limit 1048576)
#+END_SRC

The dispatcher receives the worker's portable payload, exact correlation identity
=(:session STRING :request-id INTEGER :call-id INTEGER)=, opaque host-local context,
and a cancellation predicate. It runs in a supervised host thread. Capture and
bind application dynamic context explicitly in the dispatcher. The library knows
nothing about application tools, permissions, tracing or accounting policy.
Use =sbcl-worker-host-context= in the worker to retrieve =:worker-context=.

Call IDs start at one within each evaluation. Sequential callbacks are permitted.
A callback may invoke a different worker. Nested worker callbacks, callbacks from
spawned worker threads, and requests to the same worker during host dispatch are
rejected. The host validates the complete identity and expected sequence before
calling the dispatcher; the worker validates the complete reply identity.

Portable values are NIL, T, keywords, strings, rational numbers, finite single
and double floats, proper lists and simple vectors. Trees must be acyclic, at
most 64 levels deep, and at most 65536 visited nodes. Request and result limits
count printed characters and default to 1 MiB, configurable from 256 characters
to 16 MiB. Protocol envelopes have a separate 4096-character allowance. Printing
is bounded before transport publication. Callback readers enforce the character
and nesting limits and reject reader evaluation, labels and sized-array syntax.
An oversized final evaluation response is replaced by a bounded error response.

Catch =sbcl-worker-host-error= in worker code to handle host failures. Inspect
=sbcl-worker-host-error-code=, =sbcl-worker-host-error-identity= and
=sbcl-worker-host-error-remote-type=. A host exception produces =:host-failure=
and its class name, without transporting its arbitrary report. Common protocol
codes include =:bound=, =:non-portable=, =:identity= and =:reentrancy=.

The host polls =:cancel-p= while awaiting the worker and during dispatch.
Cancellation raises =:cancelled= on the host, marks the dispatcher cancellation
predicate, interrupts the supervised thread with unwinding, and discards the
worker process. Worker death similarly interrupts active host work. A nonlocal
host exit cleans up the evaluation. Host pipe EOF raises =:disconnected= in the
worker, which then exits its normal protocol loop. Supply a deadline predicate
when host operations or worker computations need a time limit. Dispatchers must
permit ordinary Lisp thread interruption and clean up their external resources
in unwind-protect forms.
